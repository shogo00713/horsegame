## はじめに

このファイルでは、そもそものどのようにこのゲームのような Web のアプリが動いているのかをまとめ、それを言語化していきます。

各コンポーネントがどうこう、というよりは、そもそものプログラム全体がどのように動いているのかというレイヤの話です。

## サーバーとの通信

この Webアプリ は、最初に読み込む以外一才サーバーとの通信を挟まずに動いている

* 最初に読み込むのは、 HTML, JS, CSS が1本ずつと、画像数枚だけ
* イメージとしては、オフラインで全てが完結するゲームみたいな感じ
* SPAであり、特に API を使用した通信とかも行っていない

## DOM について

Reactは仮想DOMなんだとかよく言われるが、そのDOM

### DOMとは

Document Object Model の略

* 実際のブラウザの画面は、HTMLを表示しているというよりは、このDOMを表示している
* HTMLをブラウザでさらに表示しやすいように整えたイメージ
* さらに、HTMLにJSを作用させれるようにしているという役割もある

### HTML と DOM 

HTML

* 画面を書くHTMLファイルは、あくまでテキストファイルの設計図にすぎない
* HTMLの書き換えを行うには、ファイルそのものを編集するしかない

DOM

* DOMは、ブラウザがHTMLを読み込んで、メモリ上で作るもの(動的)
* DOMは、木構造のオブジェクトの形式をしており、各デバイス(ブラウザ)のメモリ上にのみ存在する (実際にプログラマーが構築・操作するものじゃないからイメージしずらいね)
* 実際のブラウザで見える画面は、このDOMをブラウザが描いたものである

### JSとの関わり (DOMの操作)

* HTMLは文字列の静的ファイルだから、JSが好きに書き換えることができない
* なのでJSでは、DOMの方を操作するといく設計になっている
* つまりJSのコードは、実際にはDOMの操作として働いている、主要なのは次の5つ
    1. 取得
    2. 作成
    3. 変更
    4. 挿入/削除
    5. イベント操作

* 他にもJSのコードの作用するところはある、計算・データの保持・タイマー・`localstrage` の管理 など

## JSX / TSX について

JSX は、JS中にHTMLをそのまま書ける便利な記法である

実際は、ビルド時に JSX で書いたものが、JS に変換されることとなっている

書き方は別途暗記しましょう



## React について

`const root = ReactDOM.createRoot(document.getElementById("root"));` によって、この `#root` の中身は今後 React が責任を持つことを宣言している (=書き換えは React のみが可能とする)

React は特に次の4つのことを担当する

1. 担当する箱はどれか = `#root`
2. その箱の中は、今どんな設計図が反映されているか (前回の結果が何であったか)
    * 今の状態がどのようになっているのかを全て保持しておく
3. 再描画のためのスケジューリング
    * 状態に変更があった時、それらの更新をまとめて、どのように再描画していけば良いかを決める
    * 必要な関数を呼び出して、再度 React Element を作る
    * 前回と今回の React Element から、違いを見つける
4. 仮想DOM
    * 設計図で、違いがある部分の木だけを、差分として新しくDOMを構成する(このことをReactの差分DOM)という


これらの記録から、前回と今回の差分を計算することができる

## ブラウザの働き

指定したURLのデータを撮りに行っているだけと思っていたが、ブラウザしたいにも画面の描画にあたって大事な働きをしてくれているわけだ

1. 通信
    * 指定されたURLにのサーバーに問い合わせて、欲しいデータをとってくる。キャッシュもする

2. 各ファイルの解析とDOMの構成
    * HTMLやCSSを解析して、どのように働かせるか決める
    * JSのエンジンが、JSを読んで動かす
    * HTMLやJSのデータを元にして、メモリ上にDOMを構成する

3. 描画
    * DOMとCSSから、実際の画面を描画する
    * 私たちに見えるアウトプットはここがメイン！！

4. 操作の通知
    * クリックや入力を検知して、JSに伝える

5. データの保存
    * 各サイトに専用のデータとして `localstorage` に保存してくれる


## 設計図とDOMをもう一度

ややこしいので、ここをもう一度まとめる

設計図には、**HTML（文字列）** と **React 要素（JS のデータ）** の2種類がある。対して DOM は実体で、設計図から建てられた家のようなものである。



| | HTML | React 要素 | DOM |
|---|---|---|---|
| 分類 | 設計図 | 設計図 | **実体** |
| 正体 | 文字列（テキストファイル） | JS のオブジェクトの木 | ブラウザ内の特別なオブジェクトの木 |
| 静的／動的 | 静的（実行中に変わらない） | 動的（状態が変わるたびに作り直す） | 実行中に書き換わる |
| 作る人 | 開発者が書く | コンポーネントから変換 | ブラウザ（`createElement` など） |
| 読み取る人 | ブラウザ | React | — |
| 画面との関係 | なし | なし | **あり**（書き換えると画面が変わる） |
| 重さ | — | 軽い（毎回作り直してよい） | 重い（差分だけ触る） |
| このプロジェクトでの役割 | 最初の枠だけ（空の `#root`） | 画面の中身すべて | 最終的に画面に出る実物 |

* いわゆる HTML + CSS とかで構成されているページは、HTMLがそのまま設計図として、それを元に DOM を立てて動いている
    * Astro とかもこっち側と考えて良い (設計図を作る場所がサーバー)

* 対して、Reactとかで動くページは、JSのデータを設計図として使っているイメージ、外枠だけはHTMLで作っているが


## 画面が表示されるまでの流れ

ここまで大体理解したところで、全体を流れとしてまとめる

書いたコードが、ユーザーの画面に表示されるまでを、次の3ステップに分けて考える

1. ビルド & デプロイ
2. 初回の読み込み
3. 操作

### ビルド & デプロイ

実装したコードを、ビルドして、世界のどこかのサーバーに置く瞬間。次のような操作が伴う

- TS → JS への変換 (型チェック含む)    

    * TSで書かれたコードを型チェックする、担当はTSコンパイラ (いわゆる `tsc` )
    * 型チェックがOKだったら、それを JS へ変換する、担当はVite 

- TSX → JS への変換 (型チェック含む)

    * TSXで書かれたコードを型チェックする、担当はおなじくTSコンパイラ
    * TSXを `jsx(..)` などの処理を含む JS に変換する、担当はおなじくVite

- 全体の圧縮

    次のような操作が自動で走る
    * 使われていないコード・空白・コメントの削除
    * CSSを1つにまとめて圧縮
    * 全ファイルとReactをまとめて1つのファイルにする (束ねる)

### 初回の読み込み

ユーザーが初めてWebサイトにアクセスして、実際の画面が表示されるまでに起こる処理、次の5つがある

- 必要なファイルのダウンロード

    * サーバーと通信して、必要なファイルをとってくる
    * 基本的には、`index.html` と全体の`js`、全体の`css`、静的な画像データなど

- HTMLの解析とJSの実行

    * 受け取った `index.html` を上から読んでいき、メタデータとかを把握する
        * DOMの骨格を作る
    - `<script>` で指定された `js` を読みにいく (読むのはHTMLの解析と並行、JSの実行は解析後)
    - `js` では、元の `index.tsx` に相当する部分が実行される
        - `#root` を React の担当にする
        - `root.render(<App />)` で、初回の描画を始める

- 設計図作り

    * `App` 以下の部分が動き出し、状態の初期値が決まる
    * 内部のコンポーネントが再起的に呼び出されて、全体の設計図が構成されていく
        * この設計図は、HTMLファイルではない
        * JSのデータとして構成されている、動的な設計図
        * React Element と呼ばれることもある

- DOMの描画

    * 設計図から木構造のオブジェクトのDOMが作られて、それが `#root` に差し込まれる
    * ブラウザがCSSを聞かしてくれて、全体が画面に表示さっれる

- useEffectの作用

    * useeffectで指定していた操作が最後に行われる

### 操作

初回の読み込みが終わった後は、ユーザーが操作に従って次のサイクルが回り続ける

- 関数が呼ばれる

    * 状態を操作する関数が呼ばれる
    * そのきっかけとしては、入力、クリック、タイマーなど
    * それに従い、状態が変わる

- `App()` の再実行

    * 状態の変更に従って、 `App()` がもう一度呼ばれる
    * 前と同じ処理により、全体のHTMLファイル(設計図)がもう一度構成される

- 差分の更新と描画

    * 設計図のもとで、前回と変わった部分のDOMだけを書き換える
    * 変わったDOMを、ブラウザが実際に画面に書き直す


## まとめ

* ビルド時に作られるのが、大きなJSファイル (React本体から構成)
* `App()`でつくられるのが React Element
* 描画の際に作られるのが DOM
* React は差分のDOMしか更新しないから便利
